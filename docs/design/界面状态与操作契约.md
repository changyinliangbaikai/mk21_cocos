# 界面状态与操作契约

v0.5 编码前准备。本文将[当前14种代表画面](主要界面与预览方案.md)细化为可实现、可验收的操作规则，不要求为每个状态再生成图片。本轮没有编写界面代码或验证真实交互。

战斗与收益以[系统规则与边界](系统规则与边界.md)为唯一源；局外等级、经验、形态与快照以[局外英雄养成与界面方案](局外英雄养成与界面方案.md)为准。本文补充触发、反馈、提交与返回方式，不通过按钮或动画另定发奖规则。所有预览图继续为待评审候选；Lv上限、成本与形态门槛仍是配置化原型建议。

## 1. 共用交互约束

- 坐标以 `720×1280` 设计逻辑画布为基准，**不是设备 CSS px**。点击区域至少 `64×64` 逻辑像素，主操作建议不小于 `88×88`；触区可大于图标，但相邻触区不得重叠。按设备安全区增加留白，不拉伸角色。
- 相邻主要按钮留出至少约12逻辑像素的间隔作为原型起点；广告/免费、保存/放弃等不同后果的按钮位置稳定，不因数值更新或动画跳动。
- 手指按下只显示反馈，合法抬起才提交；移出触区可取消。拖拽与点击分开识别，阈值由P0原型按设备验证。一次手势只对应一个操作，不穿透到下一层按钮；弹窗出现后不得消费上一层尚未结束的抬手事件。
- 未解锁不等于不可查看。锁定卡片保留可点击的详情入口；不可执行的升级/穿戴/召唤动作要显示原因，而不是仅变灰。选中、冷却、锁定、等级与星级同时使用文字、图标或轮廓，不仅靠颜色。
- 文本由原生UI显示，不能把整张候选PNG当作最终点击界面。费用、余额、等级、进度、技能冷却从配置与当前状态读取；长文可展开，关键按钮不缩成细字。
- 会改变资源或进度的操作进入“处理中”后锁住同一提交入口。保存成功才显示最终成功并转场；保存失败显示明确重试/返回状态，不重复扣费或补发。重试沿用同一操作结果标识；后台恢复先读已保存状态再决定展示什么。
- 动画、音效与进度飘字响应已确认结果。跳过只缩短演出，不跳过保存，也不重算奖励。页面关闭不是“领取”、取消不是“成功”。
- 关闭浮层回到其记录的来源阶段，不能统一恢复为战斗。应用退后台冻结游戏及相关音频；回来先恢复阶段，不能因UI消失而自动开始下一波。

下表中“整体保存”指相关状态作为同一逻辑结果持久化，具体存储实现由编码阶段确定；不是当前已经实现原子写入的声明。

N03当前候选“待机”服装与所选形态不一致，属于[已登记的视觉QA](../../assets/art/英雄形态与动画制作补充.md)，原生实现必须同步主像与三种动作预览。N02/N04当前图未完整显示Lv与形态小标，按本表补齐，不从静态图缺项推导为规则取消。
