# 文字视觉规范 v003

2026-09-13。用户认为v002与原预览仍有明显差距，尤其字体。本轮以此反馈为准；v002的构建、交互和无裁切检查不等于用户认可其视觉相似度。

## 差距与目标

此前GameApp的文字没有显式字体资产，依赖系统中文回退；按字号阈值启用伪粗体和薄描边，大部分内容采用自动缩字。木牌标题43逻辑像素，在450宽约27屏幕像素，字面与木牌比例偏小。原N01/N02的特征是粗圆、大字面、深墨轮廓与暖金厚度，正文也有明确的粗细层级。

字体基于同文案、同尺寸的实际排版比较选取；不将某个现成字体宣称为预览生成时的原字体。采用Resource Han Rounded SC Heavy和Medium的项目子集版本，明确对应展示和正文两种职责。

| 层级 | 形态目标 | 接入方式与初始尺寸（720逻辑宽） |
|---|---|---|
| 木牌主标题 | 金黄字面、橙色向下厚度、清晰深墨外轮廓；字面成为木牌主体 | FONT_DISPLAY；初始84，首包后细调至94与2.5逻辑字距，独立加高容器；不通过SHRINK缩回旧版 |
| 主要动作与导航 | 短文案饱满厚重；N01开始按钮和N02底栏以深墨字为准 | FONT_DISPLAY；主CTA约57、nav约38；长动作文案重新布局，保持可读 |
| 版块、英雄名、技能名、HUD | 深墨色重字，能区分名字、角色作用与真实数值 | FONT_DISPLAY；版块/卡名36～42、关键数字40～46；减少没有必要的细描边 |
| 正文、状态、注释 | 圆润但清晰，较长说明能连续阅读；保留完整效果与解锁条件 | FONT_BODY；按空间与重要性布局，不用展示字体挤满段落；小屏逐项检查 |

金面采用FFD53A、浅金描线约0.7逻辑；金色层与橙色厚度之间不要形成多道黑线。深色轮廓与正面共享位置，向下的硬阴影包住厚度；否则轮廓层下移会导致标题顶部只剩细线。皇冠下方保留可见间隙。普通信息不铺模糊阴影，浅底使用深墨色文字；彩色小按钮按对比度选白或墨色。900/500已经是真实字重，不再叠系统伪粗体。

## 本轮验收方法

1. 证明两份TTF真实加载并用于页面，不将浏览器系统回退当作加载成功；字形覆盖缺失应明确暴露。
2. 用真实Creator构建，在360×640和450×800查看营地、收藏、养成、编队、战斗与选卡；标题、长按钮、锁定状态、动态数字与技能说明无裁切或挤压。
3. 目视对比原预览、v002和v003，重点看字面占比、圆润粗细、金色厚度和信息层次；自动测试不替代这一项。
4. 验证主要原生点击与字效层不挡交互，保留字号/字体真实诊断；不重复无关的20波或音乐长测。

字体实际接入已完成。两款运行TTF使用不同文件名，已验证两个独立浏览器FontFace家族与两个成功网络请求，避免Cocos按相同basename缓存导致正文误用展示字。17:01稳定包中360×640及450×800各161项原生交互检查通过，共322项；两个视口各459个真实Label均未使用系统回退，实际字号等于设计字号，JS/HTTP/字体错误均为0，战斗短流程通过。
