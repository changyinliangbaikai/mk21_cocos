# 首版范围与试玩验收

历史开工规划 v0.5 · 本文保留首版范围、交付梯度和试玩方法。原“仅设计、尚未运行验收”的状态属于当时阶段，后续用户已授权并完成音画MVP、界面还原及v0.6试玩修复；当前v0.7继续优化连续战斗、四次Boss与打击表现。实际运行结果以各版本实施验收记录为准，真人与平台真机结果独立记录。

渠道范围于 2026-09-17 按用户要求更新：仅推进微信，原抖音适配与验收任务退出后续计划，见设计基线 D030。

规则依据：[设计基线](设计基线与决策记录.md)、[系统规则](系统规则与边界.md)、[局外养成](局外英雄养成与界面方案.md)、[界面方案](主要界面与预览方案.md)、[编码实施方案](../implementation/编码实施方案.md)。空间与判定使用[战斗空间与判定参数](战斗空间与判定参数.md)，原型数据使用[prototype-v0.5.json](configs/prototype-v0.5.json)。编码会话开始时应核验这些文件已落地且版本一致，不从截图反推数值。

## 2. 代表画面与逻辑状态

当前为14种代表画面：N01营地、N02收藏、N03养成、N04编队、N05锁定英雄详情、N06解锁成功，加S03战斗、S04结算及D01～D06六种浮层。它们对应6个主界面、7个浮层和1个锁定详情状态，不是14套互不相干的独立页面。历史S01/S02已被局外拆分方案替代。

开发应实现完整状态，不以“已有代表图”代替下列交互：

- 局外：无旧局/继续旧局、替换旧局确认；英雄拥有/锁定；经验足够/不足/满级；升级成功、解锁形态、预览、穿戴；空编队、未拥有英雄限制、未保存退出。
- 局内：初始部署、战斗、瞄准暂停、波间部署、选卡、技能库、冷静波、12位满员、首次行为引导。
- 救场与结束：首次失败、老爷爷演出/结算、第二失败、广告待决/完成/取消/技术故障/未知结果、免费恢复布阵、末波清屏、胜利、最终失败、后台暂停和恢复。
- 局中解锁新英雄时：可在波间查看结果；返回营地先保存，继续原局保持旧召唤池，下一新局才使用新英雄。

原型可以使用占位图形、形态标识与临时反馈，但按钮和状态须真实可操作；整张预览PNG覆盖屏幕不等于界面实现。14种候选图仍按各自评审状态管理，本文件不将它们批量转为approved。正式形态、动画、音频和小屏视觉在梯度C验收。

## 3. 首版毕业与重玩

首版内容完成目标为：**至少一次20波胜利＋4位英雄全部解锁＋4位英雄均达到Lv5并拥有全部12套形态。** 不要求以特定形态通关，也不额外要求每套形态穿戴打卡。

当前升级成本10/20/30/40：单英雄Lv1至Lv5共100训练经验，等效5次完整20波；四英雄从零培养共400经验，等效20次完整20波。这里是默认参数下的资源算术，不是实测完成时长。失败局完成过的波同样累积经验，因此实际开局次数可更多；提前夸作者解锁英雄不会直接送满级或形态。

全队Lv1的合理阵容应能完成标准20波。满级收集是额外目标，不作为首通条件；不得把反复刷等级变成弥补基础关卡过难的必经步骤。

毕业后仍可按原规则继续重玩、尝试卡牌与放置组合。首版不自动提高难度，不跳转无尽，也不新增满级后消费系统或强制每日事项。

## 4. 三个交付梯度

| 梯度 | 对应阶段 | 必须交付的可检查结果 | 边界 |
|---|---|---|---|
| A 首次可战斗 | P0～P2 | 锁定工具和配置；实际可运行的小规模调试波；召唤、攻击、合成、待部署/交换、三星大招、倍速；相关逻辑检查 | 只验证底层战斗与操作，不包含完整20波、全部卡牌、救场或永久养成，不能冒充用户完整目标已交付 |
| B 完整可玩循环 | P0～P5 | 20波、15卡、完整两阶段救场、全部局外养成/解锁/形态选择逻辑、14种画面的可操作状态、本机存档与经验事务；可运行版本、启动说明及实际执行的检查记录 | 正式图音可占位；广告通过明示的开发模拟器验证，不能称真实广告或微信上线已验收 |
| C 微信制作与真机 | P6～P8 | 正式批准素材、12套形态方向及复用动作、微信实机适配、真实广告和生命周期、设备性能、包体、时长与平衡报告 | 开发工具预览不是微信真机验收；真机完成也不等于已经发布上线 |

独立编码会话的执行目标为**完成B，并为C准备清晰接口**。可以在A形成中间检查点，但不能到A便结束为最终交付。C需要的形态映射、音频调度、平台结果与资源加载接口应提前留好；尚无正式素材、平台账号或真人试玩时，如实列明相应未验证项，不阻止B的本地功能原型制作。

B交付与真人体验验收分别记录：能运行及通过逻辑检查，不自动等于“已经好玩”或“时长达标”。后续用户提供试玩样本后继续体验验证；不能虚构观察记录来补齐报告。

## 5. 首次试玩协议

以下是建议起点：5名首次接触本游戏的试玩者，另做3组熟悉流程的1×/2×成对样本。记录是否同人复测，不把重复样本当新增人数。这只能发现早期问题，不能证明统计意义上的普遍可玩性。

首次试玩从干净进度、默认1×开始，允许玩家自行切速、使用正常救场或提前解锁。给出“试着守完这一局”的任务，让现有引导正常出现；观察者不预先教操作。发生求助时记录求助时点与内容，再给予必要帮助，不能将被教会的动作记为自行发现。

从初始部署画面可交互时计时，使用真实秒：

| 观察时点 | 需要记录的事实 | 不作强制要求 |
|---|---|---|
| 前30秒 | 是否找到召唤和位置、能否开战、是否看到第一次有效命中；停顿及误触发生在哪里 | 不强迫规定秒数内完成几次点击 |
| 前60秒 | 是否理解击杀得能量、是否发现合成与待部署、是否开始理解路线压力；是否求助 | 不自动替玩家合成或额外送资源 |
| 前120秒 | 是否经历自己能解释的有效组合或连锁、是否愿意继续；若未到三星，记录此前已有/缺少的反馈 | 不赠送三星，不强制释放大招，不为教程制造必死波 |

同时记录首次二星、首次三星、首次K系解锁/装备/释放的真实时间、战斗时间、波号、速度、已有能量、召唤数量与是否用过救场；未发生就记“未发生”，玩家提前离开则保留退出原因，不补造后半局数据。卡牌P系技能与三星K系技能分别记录。

第8波是现有节奏表提出的三星体验目标，不是解锁限制，也不是经济首次可达点。当前4个一星副本共160能量：初始120加前两波完整收益为156，理论上第3波内就可能达到160；若还要保留另外两路各一个英雄，需6副本共240，前五波全收益累计232，第6波内也可能达到。上述只说明资源可达，不保证布阵合理或能守住。首次二星甚至可由初始能量直接组成。必须如实记录更早达成的情况，不修改日志迎合第4/第8波叙事。

每局结束只询问少量具体问题，例如“哪一刻最想继续”“哪一步没看懂”“哪次失败知道原因”。主观答案与伤害、通关、时长等事件记录分开，不用逻辑测试通过替代魔性、爽感或音乐耐听的判断。

## 6. 时长与成长统计

每次记录配置版本、设备/运行环境、种子、英雄Lv与形态快照、速度切换、通关/失败及救场情况。时长从初始部署可操作到胜负结算可操作，记录完整墙钟耗时，并分列：战斗、初始/波间部署、19次选卡、技能瞄准与换装、救场演出/操作、设置或长暂停、广告、后台。

常规流程目标沿用1× **360～600真实秒**、2× **180～300真实秒**。用于比较的常规游玩时长包含实际选卡、布阵、技能操作和救场操作；广告、后台及事先标注的人工长暂停可另列，但必须同时保留完整墙钟数值。不能事后把阅读选卡或正常犹豫改记为“长暂停”以满足目标。

19次选卡逐次记录从可读到确认的耗时，再报总计、中位数、最长一次及其卡牌内容。不得把旧预算“每次2秒”写成已经测得的数据；失败局只有实际经历的选卡数，不能混进完整20波时长样本。中途切速的局单列，不伪装成纯1×或纯2×。

1×/2×配对除真人流程外，另用相同种子、相同战斗时刻的同一命令序列验证规则等价；两类结果分别报告。人的操作不会严格减半，不能仅将400战斗秒除以2当作2×真实总时长。

成长记录包括每局完成波数/经验、各英雄消费、首次Lv3形态解锁和满级所需的实际完成波数及开局数。原型重点看玩家是否愿意继续尝试组合、是否被迫刷等级；100/400经验的算术不替代这些观察。

## 7. 功能与异常验收

详细测试沿用并扩展实施方案的逻辑案例；下表是首版必须形成证据的结果，当前全部未执行、未通过。

| 项目 | 必须保留的验证证据 |
|---|---|
| Lv1标准通关 | 至少一名实际操作者使用全队Lv1合理阵容完成20波的运行记录；应包含一条不使用两次救场的通关记录，不能以Lv5或跳过敌人的调试结果代替 |
| 基本操作 | 召唤合法才扣款、合成仅一次消费、9＋3位移动与交换、待部署不攻击/光环、满员无配对仍能继续 |
| 完整选卡 | 分别验证任意1～4种英雄的合法编队，19次选卡始终不枯竭；专属不适用或有限卡到上限时，C010/C011/C012三张无先决条件、无叠选上限的通用卡保证有效池至少3张；从全部有效牌等权无放回抽3，同页不重复，不能卡死或静默突破规则 |
| 两阶段救场 | 独立跑通老爷爷后守完冷静波、第二次免费复活后继续、广告模拟清波、末波清屏与第三次失败；不要求真人首次试玩刻意失败或观看广告 |
| 经验与升级 | 各类合法清波仅入账一次，冷静波仍加经验，预支不提前给经验，结算不二次领取；48余额升Lv2→3消费20后余28，升级及重复点击不重复扣款 |
| 快照与形态 | 局外升级、穿戴及改编队后，旧局保持旧状态，下一新局才生效；Lv3不提前解锁三星技能，形态不改变战斗判定 |
| 中断恢复 | 战斗、选卡、清波、广告待决、升级与回到营地时中断；恢复不重复发奖/重抽、不退回已消费经验、不丢救场次数，未知广告结果保持安全暂停 |
| 真机及正式表现 | C阶段验证微信生命周期/广告、2×峰值、正式图音及形态兼容；占位资源的通过记录不代替正式素材验收 |

上述C010/C011/C012保底为v0.5的可执行性设计调整，保持总数15张，不是新增用户硬规则。它解决候选耗尽，是否让选卡足够有趣仍需试玩。

纯逻辑异常测试可使用可复现夹具注入失败、重复回调或旧局恢复；记录为技术测试，不计入真人通关率、首次体验或正常时长。真人没有自然触发某救场，也不代表该机制已经验证。

报告应区分“已执行通过”“已执行失败”“未执行”，附构建/配置版本和复现步骤。B可以交付可运行的待试玩原型，尚无真人样本时必须保留体验项目未执行；不得把这份计划本身当成通过证明。

## 8. 参数调整与实施约束

在首版边界内，攻击数值、空间/范围、刷怪时序、卡牌权重及其它已标为原型建议的参数可配置化调优；每次记录问题、改动和验证依据，同时同步配置与引用文档。调整后重新检查相应波次及1×/2×等价性，不靠减怪、强制清场或隐藏赠品凑目标。

20波、两阶段救场与免费路径、局内三星解锁K系技能、永久免费英雄解锁、永久等级与局内星级分工等用户确认核心不得擅改。新增英雄、章节、自动难度或改变首版收集范围，应单独提出变更，不在编码中悄悄扩充。

本轮产物是设计准备和交接依据，没有运行游戏、编写测试、制作运行时素材或完成真人试玩。独立编码会话应先检查v0.5文档及配置，再按B目标推进，并如实交付尚待C阶段完成的内容。
