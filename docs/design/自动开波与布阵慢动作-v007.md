# 自动开波与布阵慢动作 v007

本规则只适用于以 0.7 配置开始的新局。未完成的 0.5/0.6 局保留原波表、经济、手动开波及选位暂停规则，不迁移、不重新开局。营地明确提示“旧局第N波保留原规则；新玩法规则开新局生效”。

## 波次推进

1. 新局第 1 波进入准备状态，玩家可自由召唤和调整。点一次“开始第 1 波”后出怪，没有倒数自动剥夺首次准备时间。
2. 波内正常防守。完成后进入三选一卡牌；选牌本身没有时间限制。
3. 选卡完成时一次性应用卡牌、生成下一波队列和账本，进入 **1.2 真实秒**短倒数。倒数结束自动执行同一开波事务，无须再点开始。
4. 用户选用 1×/2×不会改变倒数长短。倒数期间打开设置、技能库、解锁说明或进行召唤/选位，倒数暂停；关闭后从剩余时间继续。
5. 切到后台、返回营地时不推进倒数。重新加载始终先到营地，点击“继续防守”后才恢复；不会在后台生成怪物或重复开波。
6. 免费复活仍进入 `freeDeploy`：保留怪物，允许玩家准备，明确继续后才推进战斗并启动既定保护时长。该准备不受选卡自动开波影响。

领域阶段仍使用 `deploy → battle → cards`。第二波起的自动准备由独立倒数记录区分；首波和免费复活没有倒数。界面可隐藏自动准备期间的重复开始按钮，领域 `startWave` 仍保留受权限检查的立即开始能力，供合法命令回放等内部流程使用。

## 布阵慢动作

| 状态 | 1×下有效战斗倍率 | 2×下有效战斗倍率 |
| --- | --- | --- |
| 正常战斗、仅查看攻击范围 | 1 | 2 |
| 战斗中选择召唤英雄、拖拽/选位/换位 | 0.2 | 0.4 |
| 技能瞄准、设置、技能库、后台、营地 | 0 | 0 |
| 首波准备、卡牌选择、自动开波倒数、免费复活准备 | 0 | 0 |

慢动作影响同一权威战斗 tick：怪物移动、英雄攻击、弹道、状态持续时间和技能冷却同步变化。它不会改写玩家保存的 1×/2×选择，也不会改写任何英雄或怪物速度参数。成功放置或取消后恢复用户原倍率；无效目标、能量不足等操作保留当前选位和慢动作，不扣款。

查看已部署英雄的范围只属于界面选中状态，不进入领域选位，不触发慢动作。技能瞄准保留原有完全暂停，避免操作语义混淆。

## 边界与存档

- 失败或波结束会清理悬挂的召唤/移动/瞄准状态、设置返回源及暂存交互，防止仍在拖拽时遮住救场或选卡。随后到达的过期放置命令因阶段权限被拒绝，不消耗能量。
- 新版重载不会恢复尚未完成的拖拽或召唤手势；设置若覆盖在该操作之上，可恢复设置，但关闭后回到正常战斗。战斗实体、队列、能量及收益账本不变。
- 下一波倒数以 `run.autoWave = { wave, remainingRealSeconds }` 保存。每最多 0.25 个有效倒数秒形成检查点，暂停/导航命令立即保存剩余值；突然断电至多多保留不足 0.25 秒准备时间，不会提前出怪。
- 自动开波与手动开波共用事务：清除计时、切换阶段、记录一次命令后原子保存。保存失败恢复最后的持久化快照并暂停，要求恢复存储后重新载入，不继续“无存档”防守。
- 低帧率的一次更新若跨越倒数结束，剩余真实时间继续推进战斗；不将倒数重复扣算为战斗时间。战斗积累器继续保留已积累的有效战斗 tick。
- 老爷爷和复活账本完全沿用原规则。老爷爷清波后选卡也可以触发下一波倒数；冷静波必须包括整个新队列，Boss/小Boss亦不获得怪物能量。免费复活共同补给、次数和保护不变。

## 配置和显示接口

现行配置文件保留历史文件名 `prototype-v0.5.json`，内部 `design_version` 为 `0.7`：

```json
"flow": {
  "auto_start_after_card": true,
  "auto_wave_countdown_real_seconds": 1.2,
  "placement_combat_scale": 0.2
}
```

会话对外提供两个只读接口：

- `combatTimeScale(): number`：已包含玩家倍速、布阵慢动作和暂停的**有效战斗倍率**。真正按 tick 播放的角色和弹道不能再乘一次该值。
- `autoWaveRemaining(): number | null`：待自动开波的剩余真实秒；暂停时返回冻结的剩余值，无计时则返回 `null`。

画面层独立的按钮、提示、倒数数字和非战斗反馈可用 UI 时钟。领域在最后击杀后已经结算进入 `cards`；界面短暂保留末杀演出不会推进战斗、重新结算或延迟账本事务。
