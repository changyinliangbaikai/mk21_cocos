# 超力英雄 · Cocos 游戏工程

基于 **Cocos Creator 3.8.8** 的竖屏 2D 游戏。当前分支默认启动 **R1.2.3 可玩实现**：15 波战斗、底部四英雄槽、三选一卡牌、一次性全局技能、十英雄碎片养成。旧 v0.7 实现保留用于历史回归，新局不再使用旧的合成升星玩法。

R1.2.3 将默认Cocos启动图替换为超力英雄Logo，并加入暖色背景、三英雄跳动与真实资源加载进度。此前首页留白、怪物入口、抽卡暂停及结束本局修复均已包含。

R1.2.0 在十英雄基础上接入完整成长循环：培养目标、队长候选、首通路线、阵亡储备、10英雄20个专精、成长实绩与8阶精英远征。运行规则与可复现验证见 [激励机制实现](docs/development/R1.2激励机制.md)。旧对局继续使用原快照，首次迁移保留原始存档；设计库仍不纳入Git。微信构建与Web构建分别验收，构建成功不等于已上传或真机通过。

发布渠道仅为 **微信小游戏**（2026-09-17 用户确认）。AI 接手构建与发布时，先阅读 [部署执行文档](DEPLOYMENT.md)，其中包含微信环境与 AppID 配置、本地 Web 验证、构建报告检查、验收标准及故障处理。

## 安装与构建

```bash
npm ci
npm run verify
```

使用 Cocos Creator 3.8.8 打开 `game/`，等待资源导入完成，在构建发布面板选择 **web-mobile**。入口场景是 `assets/scenes/Boot.scene`。运行所需美术、音频、字体及其 `.meta` 已包含在 `game/assets/`，无需额外导入根目录的素材制作库。

也可执行 `npm run build:web`。脚本使用独立工程副本，检查 Boot 场景仍为 `scene` 后才替换本地预览输出。本机 Creator CLI 曾偶发将资源 importer 改为 `*`；这种构建会被标记失败并保留上次可用输出。禁止同时用 GUI 和 CLI 导入同一工程。

完成构建后启动本地服务：

```bash
npm run serve
```

打开 [本地试玩入口](http://localhost:7457/)。服务读取 `game/build/web-mobile/`；新克隆的仓库须先构建。存档保存在浏览器本地存储。

[成长系统独立测试](http://127.0.0.1:7457/?qa=1&qaScene=incentive-menus)：内存账户解锁10英雄、Lv3专精与远征，刷新重置。

[四名新英雄独立试玩](http://127.0.0.1:7457/?qa=1&qaScene=roster)：测试账户预选新英雄、永久1级，第三技能仍通过抽卡解锁；内存存档不覆盖个人进度。

## 玩法

- 共有3名蓝色、4名紫色、3名金色英雄；新增英雄分别在通关第3、5、8、10关解锁，收藏页支持翻页。
- 开局连续三次三选一；选择英雄后点击空槽部署，完成选择即自动开战。阵亡英雄仍占槽位。
- 每波 30 只小怪，新局15波均分3批、每批10只集中投放；投放结束最多等待 5 秒后开始下一波；清场可提前。第 5、10 波额外加入小 Boss，第 15 波加入大 Boss。
- R1.0.1 调整：每只小怪提供 9 能量，从零开始击败 12 只即可首次抽卡；前 5 关仅出近战小怪，顶部不显示剩余怪物数量。新编排用于新开对局。
- 每 100 能量、每次击败 Boss 获得一次抽卡；新局英雄自带1级特色小技能，第3技能通过卡牌解锁，强化后尽快释放。选卡或瞄准期间自动减速，界面不展示“子弹时间”。
- 蓝色属性卡全面强化攻击、生命和防御。前期怪物属性和投放逐波增加，新对局保存难度快照，旧局保留原曲线。
- 英雄范围技能优先覆盖紧急威胁/Boss与怪群，并考虑其他技能的预估伤害。近战普攻仍覆盖半屏，其自动技能可处理90%纵深内的来敌；拖鞋逐个弹射，青蛙的治疗/增益与实际效果同步。
- 普攻在射程内优先解围贴近英雄的近战怪，其余优先Boss，再按各英雄自身距离选敌；预估前摇和在途伤害减少重复补刀，友方弹道失去目标可改道一次。
- 玉米炮追加2～6发后收回，显示余弹；鞋柜按生命和持续时间留场并发射拖鞋。召唤物使用各自的发射、受击及退场效果。
- 中央全局技能一次性消耗，按圆形、扇形、径向波纹设计覆盖；支持取消瞄准。正常速度可选 1、1.5、2 倍。
- 老爷爷救场与全灭免费复活每局各一次；预支只抵扣后续能量抽卡。普通/困难关最多 5 张碎片，超困难最多 10 张，每 10 张可升级英雄。
- R1 使用独立存档，只继承可识别旧档中的四名英雄等级并保留旧档原文；旧局、关卡和旧经济数据不转入新规则。暂停菜单支持保存并返回营地。

R1 不接入广告、充值或联网账号系统，救场和复活均为规则内免费机会。

## 微信小游戏

小游戏构建使用独立工程副本，在副本中压缩 PNG 和音频、启用原生资源分包，并检查包体上限，原始素材保持不变。当前方案无需自行部署 CDN。

安装 FFmpeg 后，在根目录 `release.local.json` 配置 `wechatAppId`，运行 `npm run build:wechat`。`npm run build:minigames` 也仅构建微信。输出写入 `artifacts/minigames/<时间戳>/game/build/wechatgame/`，构建报告会区分测试 AppID、包体检查和待完成的真机验收。没有 AppID 时可显式加 `-- --test-appid` 做本地测试，脚本不自动上传。

后续构建、真机测试、备案、提审和发布均围绕微信推进，见 [发布进度](docs/release/小游戏发布推进.md) 和 [待优化事项](docs/release/待优化事项.md)。抖音适配与 [材料草稿](docs/release/抖音提审材料草稿.md) 仅作历史存档，不再安排渠道工作。

微信 AppID 为 `wx130a8544c32afd2c`。“超力英雄”1.2.3已于2026-10-01上传成功，并确认覆盖已有体验版。392项测试、36文件Cocos类型检查通过；自定义启动Logo、加载动画、营地到开局抽卡过渡已在Web与微信模拟器检查，手机效果待复验。包与证据见 [发布进度](docs/release/小游戏发布推进.md)。历史 [微信文案与截图](docs/release/超力英雄-微信文案.md) 属于v0.7，备案或提审前须按当前R1玩法更新。

## 开发检查

```bash
npm run verify          # 同步配置、逻辑类型检查、自动测试
npm run typecheck:cocos # 使用本机 Creator 的真实类型声明
npm run test:r1         # R1 规则专项测试
npm run simulate:r1     # R1 确定性策略、恢复和结算模拟
npm run balance:r1 -- --stages=1,2 --seeds=16 # 合成选卡策略的数值回归
npm run feel:r1 -- --stages=1,2 --seeds=16 # 技能触达/群体击杀门槛
```

R1 运行规则位于 `game/assets/scripts/domain/r1/runtime-config.json`，卡牌文案位于同目录 `ui-cards.json`。`docs/design/configs/prototype-v0.5.json` 及 `config:sync` 仅服务历史规则回归，不会覆盖 R1。已确认的完整设计库 `design-library/` 仅保留本地；运行包已复制必要规则和资源，普通构建无需设计库。

当前 CLI 构建入口：`build:wechat`；`build:web`、`build:web-desktop` 用于本地调试和截图。默认使用 macOS Creator 3.8.8 安装路径；构建可通过 `COCOS_CREATOR` 指定可执行文件，类型检查可通过 `COCOS_CREATOR_APP` 指定应用路径。

## 版本管理范围

- `game/`：游戏源码、场景、运行资源、Cocos 设置和自动测试。
- `docs/design/`：玩法规则、数值配置和游戏设计说明。
- `docs/release/`：微信发布流程、构建配置示例、验收进度及已归档渠道资料。
- `tools/`：构建、服务、配置同步、模拟和测试辅助脚本。
- 根目录：依赖锁文件、TypeScript 配置及项目说明。

素材制作库 `assets/`、截图与浏览器记录 `output/`、构建及验收记录 `artifacts/`、历史评审和实施记录、一次性制作与验收脚本均保留在本地并由 `.gitignore` 排除。依赖、Creator 缓存和构建输出也不纳入 Git。字体许可随运行字体保存在 `game/assets/resources/mvp/fonts/`。

R1 字体许可位于 `game/assets/resources/r1/fonts/LICENSE.txt`。`tools/export-r1-assets.mjs` 和 `tools/build-r1-fonts.py` 仅在修改美术/字符集后用于重新导出，分别依赖本地设计源和原始字体；新克隆构建直接使用已导出的运行资源。
